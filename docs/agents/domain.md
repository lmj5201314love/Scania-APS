# Domain docs

本项目使用 single-context 领域文档布局。工程技能在理解项目背景、诊断问题、拆分任务或提出重构建议前，应按本文件约定读取领域上下文。

## 读取顺序

- 优先读取根目录 `CONTEXT.md`，如果存在。
- 读取 `docs/adr/` 下与当前任务相关的 ADR，若目录存在。
- 如果以上文件暂不存在，继续执行任务，不要因为缺失而阻塞。

## 预期结构

```text
/
|-- CONTEXT.md
|-- docs/
|   |-- adr/
|   |-- agents/
|       |-- domain.md
|       |-- issue-tracker.md
|       |-- triage-labels.md
|-- src/
```

## 项目领域要点

本项目是 Scania APS 预测性维护项目。后续技能在输出 issue、诊断假设、测试名称、重构建议或 PRD 时，应尊重项目既有语言和约束，尤其是：

- 使用官方 train/test 划分，不合并后重新切分。
- 避免数据泄漏；缺失值填充、特征筛选、标准化等规则只能在训练集上拟合。
- 业务成本重点关注 FN，成本函数为 `total_cost = FP * 10 + FN * 500`。
- 当前阶段是 Day 14 official test 最终观察，不根据 test 结果反向修改候选方案、结构规则或阈值。
- 不修改 `data/raw/` 下的原始数据。

## ADR 冲突

如果后续输出与现有 ADR 或项目阶段约束冲突，应显式说明冲突点，而不是静默覆盖已有决策。
